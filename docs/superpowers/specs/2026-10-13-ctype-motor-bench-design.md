# C 板电机测试台

用户要求按 `D:/hanako/basic_framework-master3 - 1` 增加 C 板配套固件。

## 范围与方案

新增 `basic_framework_ctype_usb-master`，与 A 板工程并列，共用 `motor_bench_host`。独立工程便于分别烧录、核对板级配置；在单个工程内切换板型会增加现有 A 板配置的改动，当前不采用。

从参考工程复制 STM32F407IGH6 的 Drivers、Middlewares、Inc、Src、启动文件、链接脚本及 CubeMX 配置。沿用其 12 MHz HSE、168 MHz SYSCLK、48 MHz USB 时钟；CAN1 为 PD0/PD1，CAN2 为 PB5/PB6，速率 1 Mbps。

复用现有测试台应用、协议、电机驱动及必要 BSP。构建只收录测试台需要的模块，不启动原遥控测试、底盘、云台、惯导及裁判系统。

## 行为

支持 GM6020、M3508、M2006、DM 的动态添加、移除、绑定、使能、参考值与遥测；DJI 三型支持现有 PID 设置/查询协议，DM 的 PID 沿用原实现能力。DJI 网页单位保持 rpm，驱动反馈由度/秒换算。清单上限 8，重启后为空。

保留 USB CDC 双向回调和发送队列；协议由唯一的 500 Hz 电机任务处理，守护任务 100 Hz，心跳超时约 1.5 秒全停。参考值在停止状态下拒绝写入，首次启动默认停止。USB 在 DWT 初始化后、任务启动前初始化。移除电机必须解除通道、驱动、CAN、守护实例的所有引用，避免访问已释放内存。

## 验证

先建立并运行 C 板 CAN 配置行为测试，确认新工程缺失时失败；随后运行真实生成代码，在 HAL 边界记录 CAN 引脚、时序和中断配置。编译 C 板完整 elf/hex/bin，检查链接内存布局；运行上位机已有协议测试，交叉比较 C 板 CRC 与 JS 实现。补充生命周期测试覆盖电机反复添加/移除和 CAN 过滤器回收。

本工作区没有 Git 元数据，因此保留设计与实施记录文件，不创建提交。实物 USB 枚举和电机响应须接 C 板验证。

## 后续确认与完成情况

用户后续明确要求 A/C 两板均增加 DT7/DR16 控制，并保留网页直接设置转速。已实现来源切换请求 0x0D 和状态报告 0x8E；遥控器右拨杆上档、右摇杆回中后，必须显式网页使能。切换来源、解绑选定遥控通道、急停和心跳超时清零输出；遥控掉线后不自动启动。

补齐新库堆边界、驱动/守护销毁、CAN 过滤器位图回收、USB 异步队列空间持有和满队列重连恢复；修正 DJI rpm 与驱动 deg/s 的换算，DM 速度环使用 PID 输出扭矩。默认 DM Master ID 0，每总线一台。

真实 C 测试已复现并验证上述行为，A/C 固件完整构建通过。浏览器操作通过模拟板端消息验证，实物检查边界仍按本文件验证章节执行。
