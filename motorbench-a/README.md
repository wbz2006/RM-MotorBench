# MotorBench A 板固件

本目录是当前固件主工程，基于 STM32F427IIH6、CubeMX 和 CMake/Ninja。旧的
`../basic_framework_atype_usb-master` 保留为实机可用的 Makefile 参考工程。

## 固件 1.18：所有已接入电机共用速度过渡与快速归零

将 1.17 的 4310 专用速度目标处理提取为 `controller.c` 的 `SpeedRampApply`，工厂创建的
DM4310、DM8009P、GM6020、M3508、M2006、LK9025、HT04 均在驱动控制周期中使用。
普通变速与非零目标的正负反向连续过零；最终目标精确为 0 时使用独立的快速制动速率，
保留使能和已有 PID 补偿。手动输入、黄色“快速归零”、使能预填及自动输出走同一规则。
红色停机/急停直接停机并清除过渡状态；重新使能从当前速度反馈起步，不续跑旧目标。
位置、电流及开环模式不经过速度目标过渡，网页保持普通“归零”按钮。

| 型号 | 普通变速/反向 | 目标为 0 |
| --- | ---: | ---: |
| DM4310、DM8009P、LK9025、HT04 | 100 rad/s² | 200 rad/s² |
| GM6020、M3508、M2006 | 30,000 rpm/s | 60,000 rpm/s |

上述值是内部目标变化率，不保证实际加减速及停止时间。常量统一位于 `motor_bench.h` 的
`MB_SPEED_ACCEL_RAD/RPM` 和 `MB_SPEED_ZERO_DECEL_RAD/RPM`；普通速率设为 0 可绕过过渡，
用于原始阶跃整定。DJI 在工厂将速率转换成 deg/s²；HT04 的网页速度目标和反馈为 rad/s，
本次补齐其下发到内部 deg/s 速度 PID 的转换，速率同步换算。LK9025 的速度计算修正为调用
速度 PID 并读取速度反馈源。LK/HT 停机与重新使能清除 PID 历史，避免旧计时影响首次控制；
两者也在反馈丢失或过渡计时异常时停止并同步通道状态。PID 默认值沿用，MIT 量程保持。

真实驱动回归分别覆盖七种电机的工厂参数、单位转换、不同 dt、普通/反向/零速变化率、
保留积分、零速保持使能、立即停机、断线不续跑、运动中重新使能和非速度模式绕过。
HT04 原生测试运行真实任务的一次控制迭代。网页模拟板覆盖所有型号的按钮及提示、
电流/位置模式隔离、旧固件兼容和移动端布局；`test:motor-state`、`test:guidance`、
`npm test`、`test:http` 与 Debug / Release 构建通过。

Release 已烧录并完整读回校验（64,916 字节），COM17 确认 **1.18**、运行时间持续增加。
更新前实际登记的 DM4310（CAN1 TX=0x06 RX=0x302，通道 0）和 DM8009P
（CAN1 TX=0x01 RX=0x11，通道 1）及全部 PID 已恢复并逐项读回一致；两台均停机、目标 0。
未使能实机验证运动。刷新网页至 `UI 20261021-speed-controls`，Node 服务保持运行；C 板快照未同步。

## 固件 1.14：异常计时与非有限输出停机保护（历史）

排查“一使能就满速”时发现，旧 PID 在 dt=0 时即使 Kd=0 也会计算出 NaN，
非有限值进入 MIT 转矩整数编码存在满量程输出风险。原生回归已复现此路径；
实际失控瞬间的 dt 尚未捕获，因此不能认定为唯一根因。

PID 拒绝非正、非有限或超过 100 ms 的采样间隔及非有限输入/积分状态，
在输出限幅前拒绝非有限输出；Kd=0 跳过微分除法。达妙驱动遇到异常计算
或转矩指令时发送停机并清零目标，恢复计时后保持停机，需用户重新使能。
DWT 读取会恢复 trace/cycle-counter 使能，不清零累计计数，以应对调试器退出影响。
1.13 的零速积分抑制保留。

`npm run test:motor-state`、`npm test` 及 Debug / Release 构建通过。
Release HEX 已由 J-Link 烧录，63,604 字节完整读回校验成功，COM17 确认 **1.14**。
实板在停机状态下注入计时使能关闭后，再次读取时钟恢复计数且持续增长；
已恢复原 DM8009P 登记和通道 0 速度环绑定，保持未使能、目标 0。
未进行实机使能或运动验证，固件重启后的 PID 为默认值。

## 固件 1.8：电机离线自动重连

- 保留已添加电机、通道绑定、闭环类型和 PID；断电或断 CAN 后重新接回，无需删除重加。
- 反馈超时（约 100 ms）锁定停机、清除旧目标和 PID 历史；恢复反馈后只恢复在线，必须手动使能。位置环仍在下一次使能时取当前位置为 0°。
- DJI 等待恢复主动反馈；DM4310 / DM8009P 停机时使用只读反馈查询，离线每 250 ms、在线停机每 50 ms，停机指令限频到 100 ms。添加/重连均不自动使能、不写编码器零点。
- CAN1/2 开启自动 bus-off 恢复，独立清理超过 10 ms 的未完成发送；邮箱满且已有旧帧时立即返回，健康总线最多等待 250 us，兼顾多电机发送和 USB 响应。CubeMX 的 `.ioc` 同步保留 ABOM 设置。
- 实现依据：达妙官方 `dmBots/motor-control-routine` 的 `stm32例程/dm_ctrl(f4) v1.1 裸机/User/dm_motor_drv.c`，`read_motor_ctrl_fbdata`：标准帧 ID `0x7FF`，DLC=4，数据 `[TX_ID低字节, TX_ID高3位, 0xCC, 0]`。回包沿用配置的 RX ID，仅收到真实反馈才上线。
- 此功能针对电机侧断电/CAN 断线，主板和 USB 会话需保持。刷新网页仍按既定流程清空测试通道。

需烧录本目录新固件 1.8，并刷新到 `UI 20261018-reconnect`。主机自动回归验证了驱动/协议和断线恢复状态，仍需实机拔插验收。

| 想做什么 | 怎么做 |

调试启动会**先自动编译，再下载 ELF，然后停在 `main`**——所以平时只按 F5 即可，
不必先手动构建。继续运行（F5 之后再按一次）才能使用 USB 测试台。

扩展首次使用时，在它的工具管理界面里安装所需的构建与调试工具
（CMake、Ninja、ARM GCC、ST-Link/J-Link GDB Server）。本机已装
STM32CubeCLT 1.21.0 与 SEGGER J-Link V9.48，插件通常能直接识别。

`.vscode/launch.json` 使用 ST 官方调试组件声明的
`stlinkgdbtarget` / `jlinkgdbtarget` 类型，以及官方的构建与 ELF 选择命令
（`preBuild` 与 `get-projects-binary-from-context1`）。它们不依赖 Cortex-Debug。
RTT 日志后端保持 SEGGER RTT；**调试器连接成功不等于已打开 RTT 日志窗口**，
看日志需要手动打开 RTT View。

### 调试配置中的设备名

`deviceName` 使用 CMSIS 设备库的 `STM32F427IIH6`，`deviceCore` 为 `Cortex-M4`。
CubeMX 的 `STM32F427IIHx` 是带占位符的型号表示，**不能**直接用于官方插件的
设备名称校验，否则会在烧录前报 `Device not found: No matching device`。
J-Link 的 `serverDevice` 则使用 SEGGER 的型号名称 `STM32F427II`。

## 命令行构建（可选，用于 CI 或脚本化）

日常开发不必用命令行；仅在需要脚本化/CI 构建时使用。

需要 CMake 3.22+、Ninja、ARM GNU 工具链（STM32CubeCLT 已包含，加入 PATH 即可）。
项目不绑定机器绝对路径。

```powershell
cmake --preset Debug
cmake --build --preset Debug --parallel

cmake --preset Release
cmake --build --preset Release --parallel
```

生成 `build/Debug/basic_framework_ATYPE.elf`、`.hex`、`.bin`、`.map`，
Release 产物在 `build/Release`。保留 CubeMX 的原项目名和产物名，目录名为 `motorbench-a`。
Debug 使用与旧工程一致的 `-Og` 优化，Release 使用 `-Os`；浮点 ABI 为 Cortex-M4F hard-float。

## 迁移范围与执行顺序

- 保留动态添加/移除电机、绑定通道、启停、三环 PID 配置、遥测、USB CDC 和 UART7 备用链路。
- 电机测试台当前接入 DJI M3508/M2006/GM6020 与 DM4310；原有 LK、HT、舵机等通用驱动源码也保留，尚未因此新增上位机支持。
- 保留 CAN、DWT、USB、串口、PWM、PID、守护和 RTT。整车底盘、云台、发射、遥控器、裁判系统及 IMU 应用留在旧工程，本工程不创建机器人或 INS 任务。
- 保留原有外设初始化、时钟、USB VID/PID、PID 数值及心跳超时参数。

启动顺序为 `MX_*` 外设初始化 → `RobotInit()`（DWT、日志和测试台回调）→
`MX_FREERTOS_Init()` 中的 USB 初始化 → 调度器。USB 底层保留旧工程的 DWT 延时处理。
CubeMX 默认任务仍会调用 USB 初始化，因此在 `usb_device.c` 的用户代码区增加了初始化保护，避免重复启动 USB。

电机任务每 2 ms 运行一次，独占测试台解析与遥测调用，遥测按原有 10 次分频约 50 Hz 上报。
旧工程同时由机器人任务和电机任务调用测试台，新工程移除了重复调度。电机任务栈为 1024 words，
沿用旧应用任务的预算；守护任务每 10 ms 运行，150 次超时对应约 1.5 秒。
默认任务在启动后自行删除，FreeRTOS heap 保持 30000 字节。

## 位置控制修复（固件 1.3）

修复 DJI 组合闭环掩码跳过位置 PID 的判断，补齐 M2006/M3508 的非零位置初始参数；
DM4310 支持实际切换位置模式，执行「相对角度 → 位置 PID → 速度 PID → MIT 转矩」级联。
原有速度环参数保持不变。DM 的位置、速度 PID 支持设置和读回，协议保留位 bit0 标记限幅 x1000 编码。

每次位置模式由停机进入使能时，以当前反馈位置定义 0°，目标和位置遥测统一为相对角度（deg）。
目标限幅 ±360°，DM 还受既有 MIT 绝对位置量程限制；反馈离线时拒绝使能，运行中反馈丢失则输出零。
M2006/M3508 使用转子角度，未换算减速后的输出轴角度。新位置 PID 参数仅为初始整定值。

更新时须烧录 1.3 固件、重启 Node 后台并刷新网页。通道操作为「解绑 → 点亮位置环 → 绑定 → 使能 → 输入角度」。
只切换 PID 面板的下拉框不会切换控制模式；绑定后的闭环配置锁定，避免界面与固件模式不一致。

原生回归覆盖 M2006 各位置组合掩码、DM 位置级联、目标点输出、超调反向修正、重复使能不归零、
再次使能重新归零、离线反馈及 DM 小数 PID 的真实 USB 协议往返；网页验证使用模拟连接。
离线测试不能代替实物位置保持和负载整定验证。

## 动态删除资源回收（固件 1.4）

网页通道卡片数量跟随板端电机清单增减，保留存续通道的编号和状态。
板端移除电机时，先停机并解绑引用它的通道，再从 DJI/DM 控制数组、CAN 接收表和守护表中注销，最后释放内存。
清单前移时同步更新剩余通道的清单索引。DJI 发送组只清除被删除电机的槽位，其余电机继续使用原通道。
CAN 过滤器改为记录实际占用 bank，删除中间电机后再次添加会复用空闲 bank，避免覆盖仍在使用的过滤器。
守护遍历与注销之间使用调度锁，CAN 接收表注销时保护中断访问。

原生回归直接编译实际 CAN、守护、DJI/DM 驱动和应用层销毁函数，连续增删 100 轮，覆盖已绑定删除、
空槽复用、过滤器回收、删除后继续控制及高编号通道存续。需重新烧录 1.4 固件；未执行实物删除验证。

## 绑定后闭环切换（固件 1.5）

新增 `LOOP_SET(0x0D)`：负载为 `channel_id, loop_mask`；应答 `0x8E` 为 `channel_id, requested_mask, result`。
仅修改已绑定通道：先停止实例、清除目标及控制历史，再修改驱动和通道闭环掩码，保留 PID 参数、绑定及其它通道状态。
位置环必须包含速度环，DM4310 不支持独立电流环；非法请求返回错误，不修改模式。下次使能重新采集位置零点。
配合新版后台及网页，在鱼骨图直接切换，无需解绑；网页等待应答，切换后保持停机，由用户重新使能。
PID 参数同样允许绑定后反复整定，写入参数会停机。需烧录 1.5 固件、重启 Node 服务并强制刷新网页。

## 心跳版本识别修复（固件 1.6）

心跳应答实际为 8 字节负载、13 字节完整帧；此前长度常量误设为 9，CRC 计算覆盖了 CRC 字段，
且帧头声明的长度比实际发送多一字节。后台丢弃该帧，使网页无法识别固件版本，导致绑定后的闭环切换一直锁定。
1.6 同步修正固件长度、上位机解析及模拟帧构造，增加心跳结构体长度／CRC／帧尾位置编译期断言。
原生回归使用实际固件 USB 输出，经真实主机流解析器验证心跳版本、逐字节输入和闭环切换应答。
需烧录 1.6 固件并重启 Node 后台、强制刷新网页；此修复不改变电机控制参数。
